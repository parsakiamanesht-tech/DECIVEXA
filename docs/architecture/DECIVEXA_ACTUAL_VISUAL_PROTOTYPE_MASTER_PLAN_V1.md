## 1. Purpose

This document converts the canonical DECIVEXA experience, component, state, information hierarchy, and high-fidelity specifications into a single visual prototype plan. It is the source of truth for the visual composition that will later be rendered as an actual prototype.

The prototype must prove product identity, hierarchy, trust, human agency, state clarity, contextual continuity, responsive behavior, RTL/LTR coherence, and accessibility intent.

## 2. Canonical Seven-Screen Slice

```text
TODAY → UNDERSTAND → GOAL → DECISION → COMPARISON → COMMITMENT → JOURNEY
```

These screens form one coherent visual narrative, not a mandatory wizard.

## 3. Global Visual Foundation

```text
Background       #F7F6F3
Surface          #FFFFFF
Surface 2        #F0EEE9
Text             #17161A
Muted            #69666F
Border           #DDD9D2
Brand            #7464DE

Warning          #9A6B16

```

Use warm neutral surfaces, restrained mature purple, strong whitespace, subtle borders, and minimal elevation.

Purple is semantic: Direction / Action / Selection / Focus. It is not decorative and must not become the dominant surface color.

## 4. Global Desktop Composition

```text
240px navigation | centered main content, max ≈1180px
12-column grid | 16px conceptual gap
```

Navigation remains visually subordinate to the main content.

Global screen grammar:

```text
Context
→ Orientation
→ Primary Intelligence
→ Supporting Information
→ Evidence / Explanation
→ Primary Action
→ Secondary Actions
```

## 5. Screen Master Frames

### 5.1 TODAY

Dominant question: **What matters now?**

Visual priority:

1. Current context
2. What matters now
3. Next meaningful action
4. Current journey
5. Attention / Review Required

Do not create a KPI dashboard, task wall, productivity score, or analytics-heavy layout.

### 5.2 UNDERSTAND

Dominant question: **What does DECIVEXA understand about me?**

Primary composition:

```text
Current Understanding
Why does DECIVEXA think this?
What matters
Patterns
Constraints
Correction / Review
```

The visual language must communicate provisional understanding rather than absolute truth.

### 5.3 GOAL

Dominant question: **What are you trying to change or achieve?**

Primary composition:

```text
Goal statement
Why it matters
Alignment
Readiness
Goal Ecology
Constraints
Desired Outcome
Generate Paths
```

A Goal must not visually collapse into a large task.

### 5.4 DECISION

Dominant question: **What am I deciding?**

Primary composition:

```text
Decision question
Why now
What matters
Constraints
Risks / Dependencies
Options
Compare Options
```

Do not show a premature winner.

### 5.5 COMPARISON

Dominant question: **Which path fits me better?**

Primary composition:

```text
Three genuinely different options
Meaningful comparison dimensions
Trade-offs
DECIVEXA'S VIEW
Reasoning
Recommendation
Choose
```

No universal score. No artificial numerical winner.

### 5.6 COMMITMENT

Dominant question: **What am I committing to?**

Initial state:

```text
Selected path
What this means
Trade-offs
Dependencies
Expected change
UNCOMMITTED
Commit Decision
```

Committed state:

```text
✓ COMMITTED
This decision is now part of your active direction.
```

The distinction `SELECTED ≠ COMMITTED` must be visually unmistakable.

### 5.7 JOURNEY

Dominant question: **Where am I going and what comes next?**

Primary composition:

```text
Desired Outcome
Path
Current Position
Milestones
Obstacles / Dependencies
Next Meaningful Action
```

The path is a navigation metaphor, not a Gantt chart or project timeline.

## 6. Shared State Treatment

States are first-class visual primitives.

Understanding:

```text
CURRENT / CORRECTED / REVIEW REQUIRED
```

Decision:

```text
UNCOMMITTED / COMMITTED
```

Proposal:

```text
PROPOSED / ACCEPTED / APPLYING / FAILED-INCOMPLETE / APPLIED
```

Outcome:

```text
UNKNOWN / INCOMPLETE / COMPLETED / FAILED
```

Every state uses text + structure/shape + semantic color. Never color alone.

## 7. Prototype Visual Rules

### Must

- calm, intelligent, human, precise
- editorial minimalism
- generous whitespace
- semantic grouping
- clear primary action
- visible state transitions
- contextual intelligence
- evidence available through progressive disclosure
- human agency visible
- same visual DNA across all screens

### Must not

- generic SaaS dashboard
- Notion/Linear imitation
- AI chatbot
- futuristic AI aesthetic
- neon/cyber styling
- glowing networks
- giant AI avatar
- excessive charts
- gamification
- purple-everywhere surfaces
- universal scoring
- decorative motion

## 8. Responsive Visual Plan

Desktop uses sidebar + centered content.

Mobile uses a bottom navigation and a single-column hierarchy.

The rule is:

> Same meaning, different composition.

Mobile is not a compressed desktop.

## 9. RTL / LTR Visual Plan

The prototype must support both RTL and LTR.

Validate:

- navigation
- directional affordances
- mixed-language content
- comparison structures
- dates/numbers
- modal composition
- action placement
- path direction

## 10. Accessibility Visual Intent

Prototype must visibly support:

- logical focus order
- visible focus
- accessible dialog behavior
- keyboard operation
- non-color-only states
- readable hierarchy
- sufficient contrast
- appropriate interaction targets

## 11. Visual Review Checklist

Before Founder Visual Validation, review:

- Can a new user identify the purpose of each screen in approximately five seconds?
- Does the interface feel like a Personal OS rather than a productivity app?
- Is the main intelligence obvious without visual noise?
- Is system understanding distinct from recommendation?
- Is recommendation distinct from user choice?
- Is choice distinct from commitment?
- Does Journey feel like navigation rather than project management?
- Does the interface communicate complexity without exposing unnecessary system complexity?
- Is purple restrained and meaningful?
- Does whitespace improve comprehension?
- Are cards used only where semantic grouping exists?
- Does mobile preserve meaning?
- Does RTL preserve meaning?
- Are states understandable without color?
